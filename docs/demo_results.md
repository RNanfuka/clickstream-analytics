# Phase 1 smoke-test evidence (synthetic retail fixture ONLY)

These results were generated by executing the local pandas pipeline with:

```bash
python -m omnihealth.cli run \
  --input data/samples/synthetic_retail_events.csv \
  --output-dir artifacts/demo \
  --source-type synthetic_fixture
```

## Verified fixture output

| Check | Observed |
|---|---:|
| Fixture input records | 28 |
| Valid event rows | 28 |
| Rejected rows | 0 |
| Unique fixture visitors | 5 |
| Inferred sessions | 8 |
| Sessions containing retail transaction events | 4 |
| Session transaction-presence share | 50% |
| Distinct order IDs counted within sessions | 4 |

**Critical:** The 50% figure is **artificial** and solely a consequence of the hand-authored test fixture. It is **not** a RetailRocket benchmark, marketing conversion rate, clinical outcome, model result or campaign-performance claim. It is not suitable for portfolio performance claims.

SQL views were queried and reconciled with the processed event and session records. The test suite also verifies rejection auditing, timestamps, session boundaries, order deduplication within sessions, data lineage, and the failure threshold.

## How to produce real observations

Download the licensed RetailRocket `events.csv` into `data/raw/`, run the real-data command in the root README, then create a **separately named real-data EDA report** from `artifacts/retailrocket/`. Never copy this fixture's numbers into a real-data report.

## Execution boundary

The latest [measured verification record](results/verification.json), generated on November 11, 2026, records **47 tests passing locally**, including four Spark cases. The environment uses Python 3.11, PySpark 4.3, and Java 17.

The Spark checks verify the fixture's exact totals: 28 events, 8 sessions, 4 converted sessions, and a 0.5 conversion rate. Additional cases compare Spark and pandas with 30-minute and 5-minute inactivity thresholds, including an exact boundary, a gap beyond the boundary, unordered input, multiple visitors, and retained duplicate actions. A rejection-threshold case verifies that rounded reports cannot weaken the quality gate.

Reproduce the full suite from an activated environment with:

```bash
OMNIHEALTH_TEST_SPARK=1 python -m pytest -q
```

These checks use small synthetic inputs. They do not establish performance on the full RetailRocket dataset or on a distributed cluster.
